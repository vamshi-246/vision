## 2. Golden model
`model/golden.py` is the oracle: 8-bit gray; 3x3 Gaussian `(sum+8)>>4`; Sobel `|Gx|+|Gy|` (11 bit); direction by `32|Gy|<=13|Gx|` etc.
(four sectors); NMS keeps `m >= earlier neighbour and m > later neighbour` (raster-asymmetric tie rule); class 0/1/2 by two thresholds;
each 3x3 stage shrinks the valid region, giving a three-pixel zero border. The group-mate wrote a separate implementation of the same
contract; run on his 10 images, **all 70 stage arrays (7 stages x 10 images) are bit-identical** to this tree's model.

## 3. Verification (all re-run on the frozen sources)
* Core RTL vs model, Verilator, sizes 7x7 .. 640x480: 18 runs, all PASS; at 640x480 33 frames per mode including the 10-image
  corpus (6 natural, 4 synthetic) at his 64/192 thresholds. Compared stage by stage: Gaussian, Sobel magnitude+direction, NMS,
  coordinates, class, histogram.
* Unit benches (11), stress suite (Sobel extrema + 100,000 random windows, **exhaustive 4,169,764-case direction test**, NMS ties,
  histogram saturation/clear, line-buffer restart, reset, APB, CRC) all PASS.
* Seven deliberate RTL mutants (Gaussian rounding, Sobel magnitude, NMS tie, coordinate alignment, histogram last pixel, row order,
  **Espresso block**) are each caught by the scoreboard.
* Full video path (`edge_video`: 4 views x 4 threshold presets, built-in pattern **and** stored-image source), 64x48 and 640x480:
  28 runs (14 with the stored-image source), all PASS (display timing, blanking, borders, RGB, core alignment, edge counts).
* RV32 SoC acceptance test (`tb/soc/tb_soc.sv`): real firmware on PicoRV32 inside the real video pipeline; mailbox values (edge count,
  thresholds in effect, all 64 histogram bins) equal the model in 6 scenarios (no-CPU fallback, four switch presets, host override); a corrupted
  expectation makes it FAIL.
* Routed-netlist functional simulation with TMDS decoding: Zybo **PASS routed TMDS timing: words=3581 active=2000 controls=1581, three lanes decoded**; Z7 **PASS routed TMDS timing: words=3581 active=2000 controls=1581, three lanes decoded**
  (summaries post-date their bitstreams).
* Not passed / open: the **post-route SDF timing simulation** (slow and fast corners) is unresolved: earlier runs showed unknown decoded
  data and an OSERDES reset-hold warning in the vendor transmitter; it was not completed and is not claimed. Boards were programmed with
  the explicit debug override `P7_HW_DEBUG=1` for that reason.

## 4. Boolean minimisation (Espresso)
`logic/espresso_direction.py` (PyEDA's binding of the Berkeley Espresso engine) minimises the 4-input function that follows the two Sobel
comparators (`c0`, `c2`, sign bits) and selects the gradient sector / NMS neighbour pair, using the don't-care rows (`c0&c2` only when
Gx=Gy=0). Canonical minterm cover: **10 terms / 40 literals**; minimised: **4 terms / 10 literals**
(4/10 without don't-cares). The cover is checked against the specification on all care rows,
the generator writes `rtl/dir_decide.sv`, and the shipped `sobel.sv` instantiates it:

    dir[1] = (~c0 & ~sx & sy) | (~c0 & sx & ~sy) | (~c0 & c2)
    dir[0] = (~c0 & ~c2)

It is verified by the exhaustive direction test and the full regressions above.

## 5. Resources, timing, latency
Same Vivado 2024.2 out-of-context flow (xc7z010clg400-1, place and route, 10 ns clock; "fmax" = 1/(10 ns - WNS) is an estimate)
for every design (`scripts/compare_resources.py`):

| design | LUT | FF | RAMB36 / RAMB18 | DSP | WNS at 10 ns |
|---|---|---|---|---|---|
| OURS (edge_pipeline, shipped core) | 2108 | 3080 | 0 / 6 (3 tiles) | 0 | -1.47 ns (fmax about 87 MHz) |
| BASELINE (plain Sobel + 1 threshold) | 125 | 206 | 0 / 2 (1 tiles) | 0 | +6.08 ns (fmax about 255 MHz) |
| PAPER system (our front end + paper engine) | 7485 | 9475 | 80 / 0 (80 tiles) | 10 | synthesis only |
| PAPER engine alone (640x480) | 6206 | 8858 | 80 / 0 (80 tiles) | 10 | synthesis only |
| GROUP-MATE core_top (his RTL) | 759 | 1521 | 1 / 7 (4.5 tiles) | 0 | +3.13 ns (fmax about 146 MHz) |

The Z7-10 / Zybo have 60 RAMB36 (120 RAMB18), 17,600 LUT, 35,200 FF. **The paper engine needs 80 RAMB36 and does not fit**
(synthesis only is reported). The streaming core needs 3 BRAM tiles and no DSP (every multiply is shift-add).
The group-mate's core is smaller (different feature set, e.g. a 16-bin histogram where this tree keeps 64 bins readable by the CPU); the
64-bin histogram is the dominant part of this tree's area. This tree had first measured 3379 LUT / 4318 FF; removing the redundant histogram snapshot copy
(proved equivalent, histogram tests unchanged) gave the current figure.

Complete board design (core + video + HDMI transmitter + JTAG-AXI + 320x240 frame store + PicoRV32 SoC), original Zybo build:
7913 LUT, 6683 FF, 24 RAMB36, 7 RAMB18; post-route **setup 7.045 ns, hold 0.023 ns, 0 failing setup / 0 failing hold endpoints** of 22843
(Z7 build: 7912 LUT, setup 8.056 ns, hold 0.022 ns). The pixel clock is generated by one MMCM at **25.178571 MHz**
(serial clock 5x; 800x525 raster = 59.95 Hz), timed against a 39.716 ns clock. Four TMDS output pins have no external receiver timing budget:
this is not an HDMI electrical-compliance claim; the signal is DVI-compatible RGB without audio.

**Latency:** `tb/video/tb_latency.sv` measures 687 clocks from a pixel entering the core to its class at a 224-clock line, i.e. 3 lines + 15 clocks;
at the product's 800-clock line the class of a pixel is available **2,415 clocks = 3.02 lines** after the pixel entered the core
(the same depth as the 2,415-stage alignment delay line in `edge_video`, so the displayed views stay aligned; the alignment-fault LED stays off on hardware).
Including the 2-clock stored-image fetch the path from the raster generator to the display is 2,417 clocks = 96.0 us at the pixel clock.

Reading: the paper's adaptive threshold marks many more pixels than the fixed 192/64 double threshold (higher recall, lower precision);
against Canny the fixed-threshold strong+weak map of this design scores F1 0.772 versus 0.685 for the paper's strong map.
Against the project golden model the "ours" row is the reference itself (trivially identical) - only the paper and baseline rows are informative.
Both references have limits (Canny parameters were chosen once, not tuned) and the conclusions hold for these images only.
Cost: the paper needs a whole-frame buffer (80 RAMB36, 10 DSP, 6206 LUT alone) and a frame of latency before
the first classified pixel; the streaming design needs 3 BRAM tiles and about 3 lines.

## 7. Formal verification (NuSMV 2.6, CTL, plus deadlock check)
`formal/run_ctl.py` exports the **shipped RTL** (Yosys `write_smv`, reduced raster sizes, reset state as initial state) and checks each property in its own
NuSMV run. Note: `ctrl_sync.sv` is a reference/timing-checker module used by tests; the shipped design generates the raster in `vga_timing`
and tracks coordinates in `linebuf`, so `vga_timing` is the primary proof target.

*vga_timing (H_TOTAL 6, V_TOTAL 5):*

| property | result |
|---|---|
| P1 horizontal counter bounded (h < H_TOTAL) | TRUE |
| P2 vertical counter bounded (v < V_TOTAL) | TRUE |
| P3 SOF only at the raster origin | TRUE |
| P4 a new frame can always start (AG EF sof) | TRUE |
| P5 end of frame is always reachable (AG EF eof) | TRUE |
| P6 end-of-line only inside active video (eol -> de) | TRUE |
| P7 line wraps: last column -> column 0 | TRUE |
| P8 raster wraps: last cell -> origin | TRUE |
| P9 active video recurs (AG EF de) | TRUE |
| P10 EOF implies EOL | TRUE |
| transition relation total (no deadlock state) | TRUE |

| RTL mutant | caught by |
|---|---|
| M1 line one cycle too long | P1, P7, P8 |
| M2 frame never wraps (v stuck at last line) | P8 |
| M3 SOF one pixel late | P3 |
| M4 EOL one pixel late (outside active video) | P6 |
| M5 vertical counter never advances | P5 |

*ctrl_sync (3x3):*

| property | result |
|---|---|
| S1 out-of-range coordinate always raises sync_error | TRUE |
| S3 clean stream reachable again (AG EF no error) | TRUE |
| S4 a protocol-conformant frame start is reachable (AG EF x=0,y=0) | TRUE |
| transition relation total (no deadlock state) | TRUE |

| RTL mutant | caught by |
|---|---|
| C1 error flag never set | S1 |
| C2 line end ignores IMG_W | S1 |
| C3 row counter never wraps | S1 |

The group-mate's abstract FSM model (`formal/abstract/`, 11 properties, 8 mutants) was re-run with the official NuSMV and reproduces his matrix
exactly (every mutant caught); his honest finding stands: `AG EX TRUE` is vacuous as a deadlock check (NuSMV's `EX` ignores deadlock states), so
deadlock freedom is taken from NuSMV's total-transition-relation check. Limits: proofs are on reduced-size instances of the parameterised RTL;
inputs are unconstrained for `ctrl_sync`; no equivalence proof between the abstract model and any RTL; the line buffer's coordinate tracker
is covered by simulation, not CTL.

## 8. Hardware demonstration (original Zybo)
Observed: monitor shows the stored photo and the original/smoothed/edge/class views, switch thresholds and BTN1 work (confirmed by the user
for the pre-CPU bitstream and the first CPU-less upload build). On the final bitstream (SHA-256 `9eda5a033b70b4e08742d474b4e80f983121451d2cc808f11b7d8a223d94413f`; the monitor picture of *this* CPU build is still to be confirmed by eye - registers and LEDs report no alignment fault):
* photo upload over JTAG, 76,800-byte read-back identical, firmware read-back identical;
* PicoRV32 running (`cpu_trap` 0, `alignment_error` 0); the **CPU-read edge count and all 64 histogram bins equal the model** for two different
  photos; the host override `threshold 30 90` changes the CPU's thresholds on the running board and the counts follow the model.
Architecture of the SoC: `rtl/soc` (PicoRV32 RV32I from `third_party/picorv32`, ISC licence; 8 KB RAM; mailbox; APB3 master to `rtl/apb_regs.sv`),
firmware `fw/src/main.c` (600 bytes; re-asserts its APB control bit every frame, because BTN0 resets the register bank - a bug found on hardware: after BTN0 the pipeline had silently fallen back to the switch presets), host tool `scripts/fpga_image.py`, address map in `rtl/video/frame_store.sv`.
DMA: not implemented; the BRAM frame store is the stated substitute. The CRC register of the APB bank is not wired to a CRC of the edge map
(reads 0). The stored image is 320x240 (shown 2x) because a full 8-bit 640x480 frame (2.46 Mb) exceeds the chip's 2.16 Mb of block RAM.

## 9. Boards
`P7_BOARD=zybo` (original Zybo; clock L16, BTN0 R18, HDMI_OUT_EN F17; pins from Digilent `Zybo-Master.xdc`) and `P7_BOARD=zybo_z7` (Zybo Z7-10; clock K17; pins
from `Zybo-Z7-Master.xdc`). Both build with 0 critical warnings and pass the routed-netlist functional simulation. Only the original Zybo has been
run on hardware. Programming scripts refuse to run without naming the board, because both boards share the xc7z010 JTAG ID.
A Z7 smoke test on real hardware is the first thing to do when a Z7 is available; nothing else in the design is board specific.
